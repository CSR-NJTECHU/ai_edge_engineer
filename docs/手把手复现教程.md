# 手把手复现教程：ROS 2 + FunASR 中文语音转文字

> 本文档由一次**完整真实运行**的过程整理而成：所有命令都实际执行过，所有"预期输出"都是
> 真机（VMware Fusion 虚拟机，Ubuntu 26.04 LTS，arm64，4 核 / 7.2GB 内存）上看到的结果，
> 耗时数据可作为你的参照基准。照着做就能从零复现「音频文件 → 中文文字」的完整链路。

## 0. 你将得到什么

```
输入音频            ROS 2 ASR 节点           FunASR 模型            识别结果
samples/test.wav → asr_node.py   ------>   paraformer-zh  ----> 「你好，欢迎学习 ROS 2！」
                    /ai/recognize_audio                          返回 Service + 存 result.txt
```

实测效果（真人录音，16kHz/单声道/16bit）：

| 音频 | 时长 | 识别结果 | 推理耗时 |
| --- | --- | --- | --- |
| 001.wav | 3.6s | 把东西从a点移到b点。 | 0.90s |
| 002.wav | 1.8s | 查询当前状态。 | 0.79s |
| test_long.wav | 9.4s | 你好，欢迎学习语音识别。今天我们把中文语音拽文字接入机器人系统，这是第一段测试音频。 | 2.11s |

## 1. 前置条件

| 项目 | 要求 | 说明 |
| --- | --- | --- |
| 操作系统 | **Ubuntu 26.04 LTS**（amd64 或 arm64） | ROS 2 Lyrical 的 Tier 1 平台。Windows/Mac 用户请用虚拟机 |
| 内存 | ≥ 4GB（推荐 8GB） | paraformer-zh 推理实测约占 2GB |
| 磁盘 | ≥ 10GB 空闲 | 模型权重约 2.1GB + torch 约 1GB |
| 网络 | 能访问 ModelScope（首次下载权重用） | 之后可完全离线 |
| Python | 系统自带 3.14 即可 | 无需自己装 3.8–3.12 |

> **Mac 用户注意**：macOS 对 ROS 2 只是 Tier 3 支持，没有二进制包，源码编译动辄数小时
> 还经常失败。**不要在 Mac 上装 ROS 2**，直接开一台 Ubuntu 虚拟机（VMware Fusion /
> Parallels / UTM 均可），本文档的场景就是这样验证的。

## 2. 阶段一：安装 ROS 2 Lyrical

### 2.1 添加 ROS 2 软件源

```bash
sudo apt update
sudo apt install -y curl gnupg lsb-release
sudo curl -sSL https://raw.githubusercontent.com/ros/rosdistro/master/ros.key \
  -o /usr/share/keyrings/ros-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/ros-archive-keyring.gpg] \
  https://mirrors.tuna.tsinghua.edu.cn/ros2/ubuntu $(lsb_release -cs) main" \
  | sudo tee /etc/apt/sources.list.d/ros2.list >/dev/null
```

> 国内用清华镜像快；海外把 URL 换成 `http://packages.ros.org/ros2/ubuntu` 即可。

### 2.2 安装 ROS 2 基础包和编译工具

```bash
sudo apt update
sudo apt install -y ros-lyrical-ros-base \
  python3-colcon-common-extensions python3-rosdep \
  ffmpeg libsndfile1 python3-pip
```

`ros-base` 已包含 `rclpy`、`std_srvs`、`ros2cli`，本项目用不到桌面版的重型组件。

### 2.3 配置环境变量（每次开终端自动生效）

```bash
echo "source /opt/ros/lyrical/setup.bash" >> ~/.bashrc
source ~/.bashrc
```

### ✅ 检查点 1

```bash
python3 -c "import rclpy; print('ROS 2 Python 环境正常')"
ros2 --help >/dev/null && echo "ros2 cli OK"
```

预期输出：

```
ROS 2 Python 环境正常
ros2 cli OK
```

> 如果报 `ModuleNotFoundError: No module named 'rclpy'`：99% 是忘了 `source /opt/ros/lyrical/setup.bash`。

## 3. 阶段一（续）：安装 FunASR + PyTorch

Ubuntu 26.04 的 pip 受 PEP 668 管理，直接 `pip install` 会被拒绝，需要加
`--user --break-system-packages`。

### 3.1 先装 CPU 版 PyTorch（顺序很重要，别用 PyPI 默认源！）

```bash
python3 -m pip install --user --break-system-packages \
  --index-url https://download.pytorch.org/whl/cpu torch torchaudio
```

> ⚠️ **真实踩坑**：在 arm64 上直接从 PyPI 装 torch，pip 会连带下载 2GB 以上用不到的
> nvidia 依赖库（nccl/cudnn 等），虚拟机磁盘配额直接爆掉（`Errno 122 超出磁盘配额`）。
> 必须指定 PyTorch 官方 CPU 源，装出来只有几百 MB，名字带 `+cpu` 后缀。

如果之前装失败过，先清缓存再重来：

```bash
python3 -m pip cache purge
```

### 3.2 再装 FunASR 全家桶

```bash
python3 -m pip install --user --break-system-packages \
  -i https://pypi.tuna.tsinghua.edu.cn/simple \
  funasr modelscope soundfile numpy
```

### ✅ 检查点 2

```bash
python3 -c "import torch; print('torch', torch.__version__)"
python3 -c "import funasr; print('funasr', funasr.__version__)"
```

预期输出（版本号 ≥ 以下值即可）：

```
torch 2.15.0+cpu
funasr 1.4.21
```

### 4.1 获取项目

```bash
cd ~

cd ai_edge_engineer
```

### 4.2 运行独立识别测试

```bash
python3 scripts/test_funasr.py
```

**首次运行会自动从 ModelScope 下载三个模型**（共约 2.1GB，实测下载速度约 28MB/s）：

| 模型 | 作用 | 大小 |
| --- | --- | --- |
| speech_seaco_paraformer_large | 中文识别主干 | 990MB |
| speech_fsmn_vad_zh-cn-16k | 静音检测、长音频分段 | ~1MB |
| ct-punc | 给结果加标点 | ~290MB |

首次完整跑通的预期输出（模型加载 82s 里大头是下载；之后权重有缓存，加载只要 17~24s）：

```
[audio] /home/你/ai_edge_engineer/samples/test.wav
        16000Hz / 1声道 / 16bit / 2.55s
[load ] 82.0s（含首次下载权重则更久）
[infer] 0.89s  RTF=0.350
[total] 87.7s
[text ] 你好，欢迎学习ROS 2。
```

再跑一次长音频，验证 VAD 自动分段和标点恢复：

```bash
python3 scripts/test_funasr.py --audio samples/test_long.wav --output outputs/result_long.txt
```

### ✅ 检查点 3

`[text ]` 一行出现了正确的中文，且 `outputs/result_long.txt` 里有带逗号句号的完整句子。

> **卡在下载怎么办**：ModelScope 权重缓存在 `models/asr/` 下（由脚本里的
> `MODELSCOPE_CACHE` 指定）。可以换台能上网的机器先跑一遍 `test_funasr.py`，
> 然后把整个 `models/asr/` 目录拷过来，效果等同离线。
>
> **关于 RTF**：RTF = 推理耗时 / 音频时长，小于 1 表示比实时快。虚拟机 CPU 上 0.2~0.4
> 属于正常水平。

## 5. 阶段三 & 四：代码结构讲解（已经写好，这里讲清原理）

### 5.1 为什么拆成两个文件

`funasr_engine.py` 是纯 Python 类 `FunAsrEngine`，负责：

* **懒导入 funasr**：`MODELSCOPE_CACHE` 环境变量必须在 `import funasr` **之前**设好，
  权重才会落到项目目录而不是 `~/.cache`，所以 import 放在 `load()` 方法里而不是文件顶部；
* `recognize(audio_path)` 返回 `(文字, 耗时)`；
* `normalize_text()` 清理 Paraformer 的输出怪癖——它会在**中文字之间插空格**、把英文缩写
  **逐字母拆开**（`你 好， 欢 迎 学 习 R O S  2！`），直接给用户很难看，函数把它还原成
  `你好，欢迎学习 ROS 2！`。

`asr_node.py` 只做 ROS 2 该做的事：声明参数、注册 `/ai/recognize_audio` 服务
（`std_srvs/srv/Trigger` 类型：空请求，返回 `success` + `message=识别文字`）、写日志。

### 5.2 节点参数速查

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `audio_path` | launch 默认 `samples/test.wav` | 待识别 wav |
| `output_path` | launch 默认 `outputs/result.txt` | 结果保存路径，空则不写文件 |
| `model_name` | `paraformer-zh` | FunASR 模型名 |
| `model_path` | 空 | 本地模型目录；**非空时优先于 model_name**（离线部署用） |
| `model_cache_dir` | launch 默认 `models/asr` | 权重缓存目录 |
| `use_vad` / `use_punc` | true | 长音频分段 / 标点恢复 |
| `device` | `cpu` | 有 NVIDIA GPU 的物理机可改 `cuda:0` |
| `batch_size_s` | 300.0 | VAD 分段后批处理的秒数 |
| `hotword` | 空 | 热词，空格分隔，如 `"ROS 语音识别"` |
| `preload` | true | 启动即加载模型（约 18s）；false 则首次请求时才加载 |

## 6. 阶段五：编译、启动、调用

### 6.1 colcon 编译

```bash
cd ~/ai_edge_engineer
colcon build --packages-select ai_asr
source install/setup.bash
```

预期输出：

```
Starting >>> ai_asr
Finished <<< ai_asr [0.76s]

Summary: 1 package finished [0.91s]
```

> 每次新开终端都要 `source /opt/ros/lyrical/setup.bash` 和
> `source ~/ai_edge_engineer/install/setup.bash`（可以都写进 `~/.bashrc`）。

### 6.2 启动节点（终端 A）

```bash
cd ~/ai_edge_engineer
ros2 launch ai_asr asr_launch.py
```

等模型加载完成（权重已有缓存时约 18 秒），看到这两行就绪：

```
[asr_node-1] [INFO] ... [asr_node]: 模型加载完成（vad=True, punc=True, 耗时 17.8s）
[asr_node-1] [INFO] ... [asr_node]: ASR Service 节点已启动，等待请求...
```

### 6.3 调用服务（新开终端 B）

```bash
source /opt/ros/lyrical/setup.bash
ros2 service call /ai/recognize_audio std_srvs/srv/Trigger "{}"
```

预期输出（`message` 里就是识别文字）：

```
response:
std_srvs.srv.Trigger_Response(success=True, message='你好，欢迎学习ROS 2。')
```

结果文件同时落盘：

```bash
cat ~/ai_edge_engineer/outputs/result.txt
```

也可以一条命令跑完检查：

```bash
bash ~/ai_edge_engineer/scripts/call_asr_service.sh
```

### 6.4 进阶：运行中切换识别目标（不用重启节点）

```bash
# 换成任意音频文件
ros2 param set /asr_node audio_path /home/你/ai_edge_engineer/samples/test_long.wav
ros2 param set /asr_node output_path /home/你/ai_edge_engineer/outputs/result_long.txt
ros2 service call /ai/recognize_audio std_srvs/srv/Trigger "{}"
```

每次 `ros2 service call` 都会读取参数的最新值，这是 `handle_recognize()` 里每次
`get_parameter()` 而不是启动时缓存一次的设计意图。

### 6.5 不用 launch 的极简启动方式

```bash
ros2 run ai_asr asr_node --ros-args \
  -p audio_path:=$HOME/ai_edge_engineer/samples/test.wav \
  -p output_path:=$HOME/ai_edge_engineer/outputs/result.txt
```

## 8. 常见问题（全部真实遇到过）

| 症状 | 原因 | 解法 |
| --- | --- | --- |
| `pip install` 报 `externally-managed-environment` | Ubuntu 26.04 PEP 668 | 加 `--user --break-system-packages` |
| 装 torch 时 `Errno 122 超出磁盘配额` | PyPI 的 torch 连带拉 2GB+ nvidia 库 | 必须用 `--index-url https://download.pytorch.org/whl/cpu` |
| `ModuleNotFoundError: rclpy` | 没 source ROS 环境 | `source /opt/ros/lyrical/setup.bash` |
| `ModuleNotFoundError: funasr` | 装到别的 Python 里去了 | 统一用系统 `python3`（即 ROS 用的那个）装包 |
| 权重下载到一半断了 | 网络波动 | 重跑 `test_funasr.py`，ModelScope 支持断点续传 |
| 权重下到了 `~/.cache` 占满 home | `MODELSCOPE_CACHE` 设晚了 | 必须在 `import funasr` 前 export（本项目已在代码里处理） |
| `ros2 service call` 卡在 waiting | 节点还没加载完模型（约 18s） | 等日志出现"节点已启动"再调用 |
| 识别结果是空的 | 音频静音或采样率离谱 | 用 `python3 -m wave` 或 ffprobe 检查是否 16kHz/mono/16bit |
| 英文字母识别错（如 "ROS"→"waf"） | 说话人口齿/合成音发音含糊 | 属模型能力极限；试试 `hotword:="ROS"`，或换真人清晰录音 |
| colcon 找不到包 | 不在 `src/` 的父目录执行 | 必须在项目根目录（有 `src/` 的那层）运行 `colcon build` |

## 9. 生成自己的测试音频

macOS（一行命令合成 + 转码）：

```bash
say -v Tingting -o /tmp/a.aiff "你好，欢迎学习 ROS 2！"
afconvert -f WAVE -d LEI16@16000 -c 1 /tmp/a.aiff samples/my_test.wav
```

Linux（把任意 mp3/m4a 转成标准格式）：

```bash
ffmpeg -i 输入.mp3 -ar 16000 -ac 1 -sample_fmt s16 samples/my_test.wav
```

> 提示：macOS `say` 合成音的英文发音含糊，paraformer 可能把 "ROS 2" 听成别的
> （真实测试结果：识别成 "waf二"）。**验收请用真人清晰录音**，本项目内置的
> `samples/001.wav`、`002.wav` 均识别全对。
